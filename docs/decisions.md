# Decisions

One line per decision taken during the build where BUILD.md left a choice open:
date — decision — reason.

- 2026-10-09 — Terraform 1.9.8 installed as a binary in ~/.local/bin (the Makefile adds it to PATH) — Homebrew could not install it (outdated Xcode CLT); only `fmt`/`validate` are used.
- 2026-10-09 — Local models (bge-small, MiniLM cross-encoder, bert-tiny) are cached in `.models/` at the repo root and downloaded by `make models` — no download at test time; the Docker image bakes them in.
- 2026-10-09 — The acceptance gate covers the phases built so far (`scripts/acceptance_gate.txt`); later phases' IDs are reported as `missing` but only fail the gate once their phase begins — §16.3 requires Step 0's `make verify` to run before any feature exists.
- 2026-10-09 — Postgres for tests runs on host port 5433 — avoids clashing with a local Postgres on 5432.
- 2026-10-10 — A semantic cache hit requires equal slots and the same context fingerprint, but not byte-identical template text — §4.1 says "same template and equal slots", yet a reworded prompt (P1-01) always has a different template; proper nouns are slots, so "France" vs "Spain" never share an answer.
- 2026-10-10 — The local embedder runs bge-small through our own onnxruntime session (fastembed only downloads/locates the files) with 2 threads and intra-op spin-waiting off — cuts light-layer p95 roughly in half when the CPU is shared; vectors are identical to fastembed's.
- 2026-10-10 — Exact-cache keys and semantic-cache entry metadata are kept in memory (rebuilt from the database at startup) — cache misses cost no database round trip; Phase 7 moves the shared index to pgvector.
- 2026-10-10 — Artifact answers are cached too (S1 step 3), labelled with the artifact's own estimate method; answers of document-backed artifacts are never cached (rule 13).
- 2026-10-10 — A `lookup` artifact must agree on every fact (verification threshold 1.0) — a single changed value (Germany 30 → 32) must demote it (P3-06), which a 0.9 threshold over ten countries would miss.
- 2026-10-10 — Verification passes only if the artifact answers at least half of the samples itself — an artifact that defers everything would otherwise score 100 %.
- 2026-10-10 — History is sent to the LLM only for context-dependent follow-ups — keeps ordinary requests lean (§4.5).
- 2026-10-10 — The local runtime keeps one persistent worker process per artifact version (python -I, scrubbed env, timeout) — a per-call process spawn would add ~100 ms+ and blow the artifact-route p95 target.
- 2026-10-10 — The demo starting state is built once by replaying the generated week through the real router and snapshotted (SQLite file copy / Postgres template database); `demo-reset` restores the snapshot (< 1 s).
- 2026-10-10 — The docker-compose Postgres runs with synchronous_commit=off — dev only: disk syncs inside Docker Desktop's VM stole host CPU and doubled light-layer p95; Aurora (prod) keeps the default.
- 2026-10-10 — Latency targets are asserted in `make perf` (no coverage tracing), not in the unit suite — coverage instrumentation slows the measured Python stages; same 25 ms threshold, still tagged P1-02.
- 2026-10-10 — Units are a slot type (UNIT, canonicalised: "kilometres" → km), and templates with the same words in a different order never share a semantic hit — from the Phase 1 review: "5 km to miles" must never answer "5 miles to km".
- 2026-10-10 — Cache entries record the artifact that produced them (`cache_entries.pattern_id`); edit, reject and demote delete them (rule 3).
- 2026-10-10 — Net savings subtract router embedding cost (`ledger.embed_cost_usd`) as well as overhead and artifact runtime; baseline stays "actual + avoided" as §4.2 defines it.
- 2026-10-10 — Bedrock model ids default to cross-region inference profiles (`us.anthropic.…`); IAM grants the profiles and their underlying foundation models.
- 2026-10-10 — The urgency `dl` artifact (and the triage artifact) arrive with Phase 5's compilers; until then S2's low-confidence fallback is exercised with a rule artifact that reports low confidence (tests/unit/test_review_regressions.py).
- 2026-10-10 — S2's low-confidence fallback step joins the browser test with Phase 5, when the urgency `dl` artifact it uses exists; until then it is covered at API level (test_review_regressions.py).
- 2026-10-10 — A knowledge prompt's "relevant" chunks are those within 0.06 cosine of the best match and above 0.60; the context fingerprint AND the LLM context use only these — so two users share a cached answer exactly when they would retrieve the same relevant sources (S4), and a cached answer can never cite a chunk outside its fingerprint.
- 2026-10-10 — A re-uploaded document is ingested as a pending version while the current version keeps serving; one transaction inserts the new chunks, flips the version and deletes the old chunks (§9.2 step 6).
- 2026-10-10 — Documents are identified by (collection, title): uploading under an existing title is a new version; the Knowledge view offers "new version" per document.
- 2026-10-10 — `chunks.tsv` is a Postgres generated column owned by the database (not in the ORM); `StrList` maps to `text[]` on Postgres so `acl && principals` uses the GIN index.
- 2026-10-10 — The SQLite path (`InMemoryRetriever`) applies the ACL and collection filters in SQL (json_each) and scores only the permitted rows in memory — rule 13 holds on both backends.
- 2026-10-10 — Every upload gets its own version number and the ingestion swap is a locked compare-and-set (newer upload or another worker wins; stale runs are discarded); the ACL is recomputed inside the swap — from the Phase 3 review.
- 2026-10-10 — Discovery clusters template-first: template groups seed clusters, groups merge at centroid cosine ≥ 0.895 (bge-small: rephrasings of one task 0.90–0.96, a neighbouring task such as routing vs triage ≤ 0.88), remaining prompts join at ≥ 0.80; a cluster is 'covered' by shared templates or by a same-task-type pattern with a near-identical centroid.
- 2026-10-10 — The trained recognizer labels earlier LLM-route traffic by the pattern that would have served it (template or centroid/exemplar match); only the rest is `none` — from the Phase 4 review (otherwise a pattern's own pre-approval traffic teaches it to reject itself).
- 2026-10-10 — Lookup artifacts are drift-sampled too, against the value the LLM extracts from the same retrieved context (in addition to re-verification on document changes).
- 2026-10-10 — Fonts are self-hosted (web/app/fonts, from fontsource) via next/font/local — the build and the stage demo need no network; same faces and weights as the deck.
- 2026-10-10 — Phase 7: ledger rollups are hourly upsert tables written in the request's own transaction (not materialized views): they are always current, and the reconciliation test holds at every instant. Unaligned ranges and per-collection breakdowns read the raw ledger; pattern payback (the ordered request at which savings overtook overhead) reads the raw rows of that pattern.
- 2026-10-10 — Phase 7: on Postgres the exact cache is an indexed `exact_key` lookup on the shared database (not an in-process key set other API tasks cannot see), fronted by ElastiCache Serverless (Valkey, `CASCADE_EXACT_CACHE_URL`): database hits are copied there for ≤ 5 min (never past the entry's expiry), invalidations and resets delete them, and every cache operation fails open to the database.
- 2026-10-10 — Phase 7: every artifact Lambda gets VpcConfig in the private (no-NAT) subnets whenever CASCADE_ARTIFACT_SUBNET_IDS is set (Terraform always sets it); integration targets must therefore be reachable inside the VPC (PrivateLink/peering), never via NAT. Locally and under moto no VPC is configured.
- 2026-10-10 — P7-05 baseline: recall@5 = 1.000 on the 21 labelled questions, measured by running the Phase 3 commit's eval in a worktree; stored in demo/data/eval/recall_baseline.json.
- 2026-10-10 — The pgvector pattern kNN computes the exact best score per pattern (DISTINCT ON over centroid + exemplars), not an approximate top-k, so the margin gate always sees the true runner-up; the table is small (patterns × exemplars). The semantic cache uses the HNSW index with strict-order iterative scans.
- 2026-10-10 — Phase 7: no connection pre-ping (it cost ~8 round trips per request). On the first disconnect SQLAlchemy invalidates the whole pool; the API answers that request 503 + Retry-After and the web client retries it once.
- 2026-10-10 — Phase 7: API tasks pick up each other's changes within 2 s — admin configuration (`CASCADE_CONFIG_REFRESH_S`, polled on requests) and the approved pattern set (`CASCADE_RECOGNIZER_REFRESH_S`, rebuilt off the request path). Pattern status is read from the database on every artifact request, so a rejected artifact never serves meanwhile. `pattern_vectors` is rewritten under a Postgres advisory lock from a fresh read.
- 2026-10-10 — P7-04 latency targets are asserted on both stores: SQLite (quick start) and Postgres + pgvector (the Phase 7 path); the load test also bounds p95 at target QPS.
- 2026-10-11 — Step D (from the whole-build review): `make demo-up` waits for the API, seeds in a one-off agent-worker container (torch lives there; the API image stays slim) and then resets through the API, so the API's artifact workers and caches start clean; `make demo-reset` also goes through the API when it is up. The seed's simulated week never waits for the on-stage Demo LLM latency.
- 2026-10-11 — A synchronous agent run (seed, the demo's lookup rebuild) takes its lease in the same write that makes it runnable, so the agent-worker can never pick it up in between. Workers, the lease heartbeat and the config sync survive dropped connections (a demo reset or a failover) instead of dying.
- 2026-10-11 — Services migrate on start under a Postgres advisory lock (API tasks and workers start together). `CASCADE_DEMO` defaults to false; compose, the e2e stack and `make api` turn it on. ML artifacts lowercase text outside the ONNX graph: its StringNormalizer needs a system locale that slim and Lambda images don't have.
- 2026-10-11 — `make demo-e2e-stack` runs the demo scenarios against the running compose stack (`PW_STACK=compose`) — the stage check; `make demo-e2e` stays the fast, self-contained run used by the build.
- 2026-10-11 — torch resolves from the PyTorch CPU wheel index on Linux (tool.uv.sources, marker sys_platform == 'linux'); the agent-worker image drops from 6.52 GB to 1.81 GB with no CUDA libraries. macOS keeps the PyPI wheel (already CPU-only). Verified by make demo-up (seed trains the dl artifact in the image) + make demo-e2e-stack 10/10.
- 2026-10-11 — `ml` / `dl` patterns carry readable Python (`Pattern.source_code`, app/compilers/source.py): the exact training recipe (`train()`, real hyperparameters) and the serving `handle(prompt)`, rendered from the artifact's meta.json; tests prove the rendered handle() matches the served model and that retraining from it reproduces predictions. Older artifacts get it rendered on read.
- 2026-10-11 — Edited ml / dl code (user's choice: fully editable, not just hyperparameters) trains through an agent run with a fixed plan (build_dataset → train_source → evaluate → report, no agent LLM tokens), so it gets the same holdout gate, ledger overhead and human approval. Locally it runs in a separate `python -I` process with a clean environment, its own session, CPU-time / file-size / open-file limits and a wall-clock kill (agent worker, never the API); on AWS as a SageMaker job with EnableNetworkIsolation. Local runs cannot block network egress — the SageMaker path is the isolated one. The artifact then serves the edited handle() as written (artifact_runner.SourceArtifact), out of process like every artifact.
- 2026-10-11 — The UI is a workspace (user's request; replaces Appendix A's top-tab layout): title bar, black activity bar (the one `nav`), per-section side panel (the Patterns explorer), editor area and a status bar in the primary blue — deck tokens and fonts only. Patterns open in an artifact editor built on Monaco (the VS Code editor), self-hosted from public/monaco (copied by next.config.js, no CDN): file tabs (handler.py / model.py / model_card.json / examples.txt), ⌘S to save or train, Test / Output / Problems panel, inspector with verification, drift, knowledge dependencies, model card and approve. TopNav, PatternCard and PatternDrawer are removed.
- 2026-10-11 — Acceptance review of the editor work, fixed: (1) edited code is never executed outside its sandboxed training job before approval — the job scores the evaluation prompts itself (predictions.jsonl) and the gate reads them (Toolbox._invoke_all), so Accept no longer runs user code in the API container; (2) in containers the local job runs as uid 65534 (cannot read the worker's /proc/*/environ), with RLIMIT_AS / RLIMIT_NPROC added, and its log is deleted after reading; (3) `integration` keys written by edited code are dropped (rule 11: only the job's approved spec); (4) SageMaker job names are `cascade-dl-src-<uuid>` (match the agent role's ARN, never collide), timed-out jobs are stopped, uploaded inputs are deleted (IAM: s3:DeleteObject on datasets/cascade-dl-*); (5) the Test panel runs non-approved versions for admins only; (6) one training run per pattern at a time (409); a source run never changes the pattern's lifecycle until Accept installs it.
